# #65 — Exportación, WIP y evaluación completa

`write_billing(run, destination)` publica juntos `ar_billing.jsonl` y `pending_wip.jsonl` en un directorio nuevo. Rechaza sin publicar los casos sin resolver, IDs repetidos, cobertura WIP inconsistente y destinos existentes. Los pendientes llevan importe, capítulos/WBS y evidencia para cierre; no generan asiento en M2.

## Reproducción

```sh
KALMORA_PHASE_DEV=/ruta/participant/phase_dev \
KALMORA_NORMALIZED_SOURCES=/ruta/participant/normalized_sources \
PYTHONPATH=src python -m unittest discover -s tests -p 'test_billing_*.py' -v
```

**37 pruebas pasan** en Python 3.12.13: 26 tareas, 25 facturas, un pendiente, 18 FACe, cero sin resolver. Evaluador oficial `participant/score.py`: **AR = 1,0**, 26/26 respuestas. También se compara fecha, moneda, bruto, deducciones y composición de líneas exacta. Los números/registry internos de golden no se exigen.

`tests/fixtures/billing-july.json` es anotación revisada de los documentos originales, creada antes de consultar golden, para verificar el motor. No es extractor de producción ni sustituye #56/#57. Cada anotación conserva hash y cita de página. `DocumentRouter(use_preparsed=True)` del mecanismo nuevo comprueba los snapshots; el test contrasta las citas de los 26 documentos y comprueba rechazo de snapshots ausentes, obsoletos, mal vinculados o con esquema inválido. No usa fallback a PDF.

En la ejecución del 2026-10-03 el lector nuevo todavía era un cambio local compartido. Se utilizó `KALMORA_ROUTER_MODULE=/ruta/src/kalmora/documents/router.py` para probar exactamente ese fichero sin copiarlo ni modificar la extracción. Una vez integrado el lector, esta variable se omite. Las pruebas necesitan el paquete dev y su golden explícito; nunca leen golden desde el motor ni phase_test.
