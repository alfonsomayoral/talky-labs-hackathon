# #64 — Factura, asiento y FACe

El motor exige los tres DIR3 para públicos españoles; su ausencia queda sin resolver. Se conservan número, moneda, bruto y leyenda RISP (art. 84.Uno.2º f) en salida, aunque no los puntúe el scorer. La ampliación opcional de ArInvoice permite validarlos sin cambiar los campos exigidos. Los asientos llevan propietario `(billing_item, ar_billing)` compatible con Ledger; asignación de cliente coincide con número de factura. Los importes de líneas deben ser céntimos enteros.

**30 pruebas M2 pasan**, cuatro específicas en `test_billing_invoice.py`. Comando: `PYTHONPATH=src python -m unittest discover -s tests -p 'test_billing_*.py' -v` con `KALMORA_PHASE_DEV` al paquete original.

La numeración se deriva de series ERP disponibles; no se inventa registry de FACe. No se emiten facturas en un servicio externo. La evaluación completa de julio con snapshots normalizados se incorpora en #65.
