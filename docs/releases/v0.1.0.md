# v0.1.0 — M0 foundation

Reviewed on 2026-10-03. This release closes M0 (data, accounting interfaces,
evaluation and traceability). It does not claim that the six accounting solvers
are complete. The backend already includes the deterministic M1 receipt
allocation and AP valuation cores, which remain part of the tested snapshot.

## Acceptance evidence

The original July ZIP has SHA-256
`c813449eab9ddc7fc28b04eff85518957035e895b5500fd19e26c0d8ef7f0109`.
Its 830 useful files are preserved byte for byte; `__MACOSX` is excluded.
The phase and month are read from the inputs (`phase_dev`, `2026-07`).

- Seven companies and 36,743 recorded journal entries are loaded reproducibly.
- The reconstructed journal exactly reproduces `trial_balance_recorded` by
  company/account. All 435 golden adjustment groups balance.
- The official scorer is loaded unchanged and checked against the registered
  manifest. Missing manifests and changed scorers are rejected.
- Golden as a submission gives **100.0**; an empty submission gives **3.54**;
  AP-only gives **36.38**. All module details reconcile with the official score.
  These are evaluator checks, not solver accuracy measurements.
- A wrong journal company is reported even when the official score is unchanged.
  Invalid enums, nested non-integer amounts, malformed JSONL, missing conditional
  fields and adjustment lines without explicit company are rejected.
- Solver modules do not import the evaluator; input access rejects golden paths.
  A golden from another month cannot be used to evaluate the solver phase.
- Execution reports include UUID, duration, inputs, status and cost assumptions;
  document facts and extraction cache retain source evidence.
- The coverage matrix and discrepancy register document policy ownership and
  rules still belonging to later milestones.

## Reproduce

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m compileall -q src
KALMORA_PARTICIPANT_ZIP=/path/participant.zip .venv/bin/python -m unittest discover -s tests -v
.venv/bin/kalmora doctor
.venv/bin/kalmora import-package /path/participant.zip --destination data/julio
.venv/bin/kalmora inspect data/julio/participant/phase_dev
.venv/bin/kalmora ledger-summary data/julio/participant/phase_dev
.venv/bin/kalmora evaluate data/julio/participant/phase_dev \
    data/julio/participant/phase_dev/golden \
    --evaluator data/julio/participant/phase_dev --text
git diff --check
```

The complete local verification passes **51 tests**, including the two optional
checks against the original ZIP. CI runs the portable suite without private
participant data on Python 3.12, for `backend`, `main`, release tags and their PRs.

## Review corrections

The comparator's structure mode previously accepted invalid enums and could
crash on malformed rows or entries. It now validates the existing output types,
writes format diagnostics, and returns a nonzero status for invalid structure.
Non-object JSONL rows identify their file and line. The documented API004469
exception now applies only to its missing supplier partner, rather than hiding
unrelated entry errors. AP amount docstrings and nullable fields are aligned
with the observed organizer output and the recorded M0 conventions.

## Remaining limits

API004469 / `1100-2026-5100000822` lacks the required supplier partner on its
407 advance line. It remains visible as `KNOWN_EXCEPTION`; source data and
golden are unchanged. `SCORER_FIELD_GAPS` remains a documented follow-up: the
comparator does not audit balance dimensions beyond company/account. September
scoring is unverified because its golden is unavailable. M1–M7 retain their
own implementation and acceptance requirements.
